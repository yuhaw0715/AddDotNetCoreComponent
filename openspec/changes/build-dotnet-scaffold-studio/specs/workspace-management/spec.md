## Purpose

提供可預測且安全的工作區選擇流程，使所有產生命令都明確作用於使用者選定的 Solution、資料夾與目標專案，而不會誤改其他專案。

## ADDED Requirements

### Requirement: 選擇工作區
系統 SHALL 允許使用者選擇 Solution 檔案或資料夾作為工作區，並在接受前驗證路徑存在且可讀取。

#### Scenario: 選擇有效 Solution
- **WHEN** 使用者選擇可讀取的 `.sln` 或 `.slnx` 檔案
- **THEN** 系統載入該 Solution 所在目錄並開始探索專案

#### Scenario: 選擇無效路徑
- **WHEN** 使用者選擇已不存在或無法讀取的路徑
- **THEN** 系統拒絕載入並以繁體中文說明原因，且不執行任何 CLI 命令

### Requirement: 探索目標專案
系統 SHALL 遞迴探索工作區內的 `.csproj`，排除 `bin`、`obj`、隱藏建置輸出與不可讀目錄，並顯示專案名稱、相對路徑、目標 Framework 及 SDK 類型。

#### Scenario: 工作區包含多個專案
- **WHEN** 探索結果包含兩個以上 `.csproj`
- **THEN** 系統列出所有有效專案並要求使用者明確選擇目標專案

#### Scenario: 工作區沒有專案
- **WHEN** 探索結果不包含 `.csproj`
- **THEN** 系統仍允許使用專案範本功能，但停用需要既有目標專案的功能並說明原因

### Requirement: 驗證命令目標
系統 MUST 在每次執行命令前重新確認目標路徑仍位於目前工作區內、目標專案仍存在，且命令預覽中的工作目錄與畫面顯示一致。

#### Scenario: 專案在載入後被移動
- **WHEN** 使用者準備執行命令但目標 `.csproj` 已不存在
- **THEN** 系統中止執行、重新掃描工作區並要求重新選擇目標

### Requirement: 最近工作區
系統 SHALL 保存最近開啟的工作區與各工作區最後選取的目標專案，但不得保存任何連線字串、Token、密碼或命令中的機密值。

#### Scenario: 重新開啟有效的最近工作區
- **WHEN** 使用者從最近清單選擇仍存在的工作區
- **THEN** 系統載入工作區並在目標專案仍有效時恢復上次選擇

#### Scenario: 最近工作區已失效
- **WHEN** 最近工作區路徑已不存在
- **THEN** 系統移除該失效紀錄、提示使用者，且不中斷其他最近項目的使用
