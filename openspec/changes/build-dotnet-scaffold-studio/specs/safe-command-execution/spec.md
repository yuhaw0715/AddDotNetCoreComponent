## Purpose

為所有外部 CLI 操作提供一致的隔離、確認、取消、記錄與差異檢視機制，降低命令注入、誤改專案及高風險資料庫操作的風險。

## ADDED Requirements

### Requirement: 不經 shell 執行
系統 MUST 以可執行檔與結構化引數清單啟動程序，不得將使用者輸入串接成 shell 指令，也不得透過 `sh`、`bash` 或 `zsh -c` 執行產生命令。

#### Scenario: 輸入包含 shell 特殊字元
- **WHEN** 使用者輸入包含分號、反引號、管線或命令替換語法的值
- **THEN** 系統將其作為單一引數驗證或拒絕，且不會執行額外程序

### Requirement: 命令風險分級
系統 SHALL 將命令分為一般、會覆寫/移除檔案及會變更資料庫等風險層級。一般新增操作可在預覽後直接執行；覆寫、`migrations remove`、`database update` 及等同風險的操作 MUST 二次確認。

#### Scenario: 執行一般新增
- **WHEN** 使用者已提供有效參數並啟動不覆寫檔案的一般新增操作
- **THEN** 系統顯示命令與目標後開始執行，不要求第二個確認對話框

#### Scenario: 更新資料庫
- **WHEN** 使用者要求執行 `database update`
- **THEN** 系統顯示目標環境、DbContext、連線資訊來源及命令，只有在二次確認後才執行

### Requirement: 單一可取消執行
系統 SHALL 同一時間只允許一個會修改工作區的命令，並在執行期間提供取消動作；取消 MUST 先要求程序正常終止，必要時再終止其程序樹。

#### Scenario: 執行期間再次啟動命令
- **WHEN** 一個修改命令仍在執行且使用者嘗試啟動另一個修改命令
- **THEN** 系統拒絕第二次啟動並將使用者導回目前執行狀態

#### Scenario: 使用者取消長時間命令
- **WHEN** 使用者選擇取消正在執行的命令
- **THEN** 系統終止該工作、標示為已取消，並重新掃描實際檔案狀態而不假定命令沒有留下變更

### Requirement: 即時且可保存的執行紀錄
系統 SHALL 即時顯示標準輸出與標準錯誤，並為每次執行保存時間、功能、遮蔽後命令、工作目錄、結束碼及結果摘要。系統 MUST 不保存已標記的機密值。

#### Scenario: CLI 輸出錯誤
- **WHEN** 外部程序寫入標準錯誤
- **THEN** 系統即時呈現該輸出，命令完成後仍可由本次工作階段的歷程檢視

### Requirement: Git 與檔案差異檢查
系統 SHALL 在可用時於命令前記錄目前分支與工作樹狀態，並於命令後顯示新增、修改及刪除檔案。系統 MUST NOT 自動 commit、stash、checkout、reset 或還原檔案。

#### Scenario: 工作樹已有未提交變更
- **WHEN** 執行前 Git 工作樹不是乾淨狀態
- **THEN** 系統顯示既有變更但不阻止一般操作，並在結果中區分執行前已存在與執行後新增的差異

#### Scenario: 工作區不是 Git 儲存庫
- **WHEN** `git` 不可用或工作區不屬於 Git 儲存庫
- **THEN** 系統略過 Git 資訊、改用檔案快照呈現差異，且不將此情況視為命令失敗
